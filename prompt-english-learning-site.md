# ЗАДАЧА: Создать сайт для изучения английского языка (группа/курс)

Создай веб-приложение на **Next.js (App Router) + React + TypeScript + SCSS**.
Это образовательная платформа для моей группы, изучающей английский с нуля.
Сайт будет расти: сейчас нужна только тема **"to be"**, но архитектура должна
позволять легко добавлять новые темы отдельными промптами в будущем — не переписывая всё заново.

## 1. АРХИТЕКТУРА (важно для будущих доработок)

- Next.js App Router, TypeScript, SCSS-модули (без Tailwind).
- Каждая тема — это отдельный объект данных (JSON/TS) + переиспользуемые React-компоненты урока.
  Структура примерно такая:
  ```
  /app
    /topics
      /to-be
        page.tsx
  /data
    /topics
      to-be.ts        <- весь контент темы (объяснение, слова, упражнения) отдельным файлом
  /components
    /lesson
      TheoryBlock.tsx
      VocabularyCard.tsx
      ExerciseFillGap.tsx
      ExerciseMultipleChoice.tsx
      ExerciseMatching.tsx
      ExerciseTranslate.tsx
      ProgressBar.tsx
      FeedbackToast.tsx (нежно-зелёный / нежно-красный)
      ResultsSummary.tsx (итоговый экран с процентом понимания темы)
  /styles
    variables.scss (цвета, шрифты)
    globals.scss
  ```
- Когда я в будущем попрошу добавить новую тему (например Present Simple),
  агент должен: создать новый файл `/data/topics/<slug>.ts`, новую страницу `/app/topics/<slug>/page.tsx`,
  переиспользуя те же UI-компоненты урока, и добавить тему в общий список тем на главной странице
  (`/data/topics/index.ts` или аналог). НЕ трогать чужие уже готовые темы.
- Прогресс пользователя (пройдено/не пройдено, результаты тестов, история попыток) хранить в `localStorage` —
  без бэкенда и базы данных на этом этапе.

## 2. МЕТОДИКА ОБУЧЕНИЯ (обязательно следовать)

Используй проверенную методику для начинающих (Presentation → Guided practice → Free practice + spaced repetition):

1. **Разогрев / контекст** — короткое, живое введение: где и зачем используется эта грамматика в жизни (1–2 примера-диалога на английском с переводом на русский).
2. **Теория (Presentation)** — объяснение **на русском языке**, максимально просто и досконально, для тех, кто видит английскую грамматику впервые:
   - что такое to be и зачем оно нужно (в русском языке аналога нет — объяснить именно эту разницу);
   - таблица форм: I am / You are / He-She-It is / We are / They are;
   - утвердительная, отрицательная (am not / isn't / aren't), вопросительная форма;
   - сокращения (I'm, he's, they're и т.д.) — отдельно, т.к. новички их не понимают на слух;
   - 5–7 очень простых примеров с переводом на каждую форму.
3. **Новые слова (Vocabulary)** — 10–15 слов/фраз, которые встретятся в упражнениях этой темы (профессии, прилагательные для описания, страны и т.д.), с переводом, транскрипцией и примером-предложением с to be.
4. **Guided practice (тренировка с подсказками)** — упражнения, где сразу видно правило, ошибаться не страшно:
   - заполнить пропуск (am/is/are);
   - выбрать правильный вариант (multiple choice);
   - собрать предложение из слов.
5. **Free practice (самостоятельная тренировка)** — усложнение без подсказок:
   - перевести предложение с русского на английский;
   - написать про себя (My name is..., I am...) — свободный ввод с проверкой ключевых слов;
   - мини-диалог с выбором реплики.
6. **Финальный тест темы** — 10–15 вопросов вперемешку (по всем формам + лексика), с процентом прохождения и возможностью пересдать.
7. **Повторение (spaced repetition)** — в конце показать 3–5 "карточек на повторение" слов/правил из этой темы, которые предлагать снова при следующем визите (простая реализация через localStorage: дата последнего повторения + интервал).

Важно:
- Объяснения — **на русском**, инструкции к упражнениям — **на английском с переводом на русский рядом**, сам изучаемый материал — **на английском**.
- Тон объяснений — как хороший терпеливый преподаватель, а не сухой учебник: примеры из жизни, немного юмора, никакого сложного метаязыка без объяснения.
- После каждого ответа — мгновенный фидбек (см. стиль ниже), с коротким объяснением, ПОЧЕМУ ответ верный/неверный, а не просто "правильно/неправильно".
- В конце каждого блока — краткое резюме ("Что мы выучили") в 3-4 пунктах.

## 3. ИТОГОВАЯ ОЦЕНКА ПОНИМАНИЯ ТЕМЫ (важный раздел)

По итогам прохождения темы (и практических упражнений, и финального теста) нужно показать
студенту **общий процент понимания темы** — не просто "результат теста", а сводную картину.

Реализуй экран `ResultsSummary` в конце темы со следующей логикой:

- **Считать процент по всем активностям темы**, а не только по финальному тесту:
  - Guided practice (упражнения с подсказками) — учитываются с меньшим весом (например 30% от итоговой оценки).
  - Free practice (самостоятельные задания) — средний вес (например 30%).
  - Финальный тест — наибольший вес (например 40%), так как это чистая проверка знаний без подсказок.
  - Веса вынести в конфиг (например `/data/scoring.ts`), чтобы их легко было менять при добавлении новых тем.
- **Формула**: процент по каждому блоку = (правильные ответы / всего вопросов в блоке) × 100,
  затем взвешенная сумма по весам блоков = итоговый процент понимания темы.
- Каждая попытка (клик "ответить") учитывается один раз на вопрос: если студент менял ответ несколько раз,
  засчитывать финальный выбор перед переходом к следующему вопросу, а не каждую попытку.
- **Визуализация результата**:
  - Крупный круговой/дуговой индикатор (progress ring) с процентом по центру, в тон общей палитре (зелёный при высоком проценте, жёлто-персиковый — средний, мягкий коралловый — низкий; без агрессивных цветов).
  - Текстовая интерпретация результата понятным языком, например:
    - 90–100% — «Отлично! Тема усвоена, можно двигаться дальше.»
    - 70–89% — «Хорошо, но пара моментов ещё требует внимания.»
    - 50–69% — «Тема понята частично, рекомендуем повторить теорию и попробовать снова.»
    - ниже 50% — «Стоит вернуться к теории — пока рано двигаться дальше.»
  - Разбивка процента по подтемам/формам (например: "Утвердительная форма — 100%", "Отрицательная форма — 60%", "Вопросы — 80%", "Лексика — 90%"), чтобы студент видел, что именно подтянуть.
  - Список конкретных вопросов, где были ошибки, с правильным ответом и коротким объяснением — под спойлером/раскрывающимся блоком, чтобы не перегружать экран.
- Результат (итоговый процент + разбивка + дата попытки) сохраняется в `localStorage` и:
  - показывается на карточке темы на главной странице (например бейдж "82%" поверх карточки "To Be");
  - хранится история попыток, чтобы студент видел прогресс от раза к разу (например мини-график или список "Попытка 1 — 60%, Попытка 2 — 85%").
- Кнопка "Пройти тест заново" — сбрасывает только тест (не весь прогресс по теории), и после пересдачи пересчитывает итоговый процент.

## 4. СТИЛЬ И ДИЗАЙН

- Общий стиль сайта — современный, лёгкий, "воздушный", дружелюбный для новичков (не строгий корпоративный).
- Мягкая цветовая палитра (пастельные, "нежные" тона), не кричащая:
  - основной акцент: приглушённый мятно-зелёный / шалфейный (например `#7FC8A9` или близкий тон);
  - вторичный: нежный лавандовый или голубой фон карточек;
  - **правильный ответ**: нежно-зелёный фон/обводка (например `#DFF5E6` фон, `#4CAF7D` текст/иконка) + плавная анимация появления галочки;
  - **неправильный ответ**: нежно-красный/коралловый (например `#FDEAEA` фон, `#E57373` текст/иконка), без резкого "агрессивного" красного — не должно пугать или демотивировать;
  - фон страниц светлый, много "воздуха" (whitespace), скруглённые углы карточек (12–16px), мягкие тени.
- Типографика: чистый sans-serif (Inter / Nunito / Poppins через next/font), крупный читаемый текст для теории, чуть компактнее для интерфейса упражнений.
- Прогресс-бар темы вверху страницы урока (сколько блоков пройдено).
- Адаптивная вёрстка (mobile-first, ученики могут заходить с телефона).
- Плавные, но ненавязчивые transition/анимации (появление карточек, фидбек, заполнение progress ring на итоговом экране), без перегруза.
- Главная страница — список тем в виде карточек (сейчас одна карточка "To Be", остальные — "скоро" / заблокированы), с индикатором прогресса и процентом понимания по каждой пройденной теме.

## 5. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

- Next.js (последняя стабильная версия), TypeScript, SCSS modules.
- Код чистый, компоненты переиспользуемые и типизированные (интерфейсы для структуры темы/упражнения/результатов в `/types`).
- Никаких хардкодов текста темы внутри компонентов — весь контент темы берётся из `/data/topics/to-be.ts`, чтобы потом легко добавлять новые темы, просто создавая новые дата-файлы.
- Логика подсчёта процента понимания вынесена в отдельный переиспользуемый модуль (например `/lib/scoring.ts`), не привязанный жёстко к теме to be, чтобы работать для любых будущих тем.
- Проект должен быть готов к деплою на Vercel без доп. настроек (никаких серверных секретов/БД на этом этапе).

## 6. ФИНАЛЬНАЯ ПРОВЕРКА (обязательный шаг перед завершением)

После того как всё написано:
1. Установи зависимости и запусти `npm run dev` — убедись, что сайт запускается без ошибок.
2. Проверь `npm run build` — убедись, что сборка проходит без ошибок и без критичных warning'ов TypeScript.
3. Пройди глазами по всем экранам темы to be: теория → слова → тренировка → тест → итоговый результат с процентом — убедись, что навигация работает, прогресс и результаты сохраняются, фидбек на ответы отображается корректно (зелёный/красный), а процент понимания темы считается корректно с учётом весов блоков.
4. Проверь адаптивность (мобильная ширина).
5. В конце коротко напиши отчёт: что реализовано, что запускается, какие есть ограничения/что можно улучшить в следующей итерации.
